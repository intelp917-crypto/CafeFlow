# ۸. مدل داده نقشه سالن (Floor Plan)

> وضعیت: **طراحی‌شده، پیاده‌سازی در فاز ۳.** جدول‌ها در `001_init.sql` ساخته شده‌اند تا مهاجرت بعدی لازم نباشد.

## موجودیت‌ها

```
floors ──1:1── floorplans ──1:n── floorplan_objects ──1:n── chairs
   │                                   │
   └──1:n── areas                      └── ref_table_id → dining_tables
```

### `floorplans`

| ستون | نوع | معنا |
|---|---|---|
| `id` | TEXT PK | شناسه |
| `floor_id` | TEXT UNIQUE FK | هر طبقه یک نقشه |
| `width`, `height` | INTEGER | ابعاد بوم (پیکسل منطقی) |
| `grid_size` | INTEGER | اندازه شبکه برای snap (پیش‌فرض ۲۰) |

### `floorplan_objects`

| ستون | معنا |
|---|---|
| `type` | `square_table`, `round_table`, `rect_table`, `chair`, `bar`, `kitchen`, `sofa`, `waiting`, `reception`, `entrance`, `exit`, `restroom`, `vip`, `outdoor`, `custom` |
| `ref_table_id` | برای میزها: اتصال به میز عملیاتی واقعی |
| `x`, `y`, `width`, `height`, `rotation` | هندسه |
| `z_index`, `layer` | ترتیب و لایه |
| `is_locked` | قفل ویرایش |
| `props_json` | ویژگی‌های افزودنی (رنگ، برچسب، شکل سفارشی) |

### `chairs`

صندلی‌ها ردیف مستقل دارند (`floorplan_object_id` یا `table_id`) تا **هر صندلی مستقلاً جابه‌جا شود**؛ دوران و برچسب هر صندلی ذخیره می‌شود.

### `floorplan_versions`

Snapshot کامل (`snapshot_json`) با شماره نسخه یکتا برای هر نقشه. ذخیره دستی نسخه می‌سازد؛ ذخیره خودکار `floorplans.updated_at` را به‌روز می‌کند. بازگردانی = نوشتن نسخه قبلی روی نقشه با ثبت نسخه جدید (تاریخچه هرگز حذف نمی‌شود).

## قرارداد ویرایشگر (فاز ۳)

- بوم 2D (بدون وابستگی سنگین) با پنل‌ها: کتابخانه اشیا (راست)، بوم (وسط)، ویژگی‌ها (چپ)، نوار ابزار (بالا).
- قابلیت‌ها: drag & drop، snap به شبکه، zoom، pan، چرخش، انتخاب چندگانه، کپی/چسباندن، گروه‌بندی، لایه، قفل، undo/redo، ذخیره خودکار (debounce ۲ ثانیه)، ذخیره دستی، ورود/خروج JSON، حالت پیش‌نمایش.
- Three.js فقط برای پیش‌نمایش سه‌بعدی اختیاری؛ ویرایشگر روی موبایل با همان 2D کار می‌کند.
- لایه عملیاتی: هر شیء میز وضعیت زنده (`available/occupied/...`)، سفارش فعال، گارسون، مدت اشغال و درخواست مشتری را از API نشان می‌دهد و اقدام‌ها (باز کردن میز، انتقال، ادغام، درخواست صورتحساب، آزادسازی) از همان REST انجام می‌شود.

## قواعد داده

- حذف میز دارای نشست باز ممنوع است (`ON DELETE RESTRICT` روی `table_sessions`).
- شیء میز بدون `ref_table_id` فقط تزئینی است و وضعیت عملیاتی ندارد.
- ذخیره نقشه در یک تراکنش انجام می‌شود: به‌روزرسانی `floorplans`, جایگزینی `floorplan_objects` و درج نسخه.
